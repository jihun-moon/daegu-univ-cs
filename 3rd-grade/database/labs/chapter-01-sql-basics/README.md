# Chapter 01. SQL 기초

## 데이터에 관심을 가져야 하는 이유

### 폭발적으로 증가하는 데이터

정보 기술의 발전과 디지털화로 막대한 양의 데이터가 생성되고 있다. 데이터 기술과 클라우드 컴퓨팅이 발전하면서 저장과 처리 비용이 줄었고, 그만큼 증가율도 더 커졌다.

그렇다면 얼마나 많은 데이터가 생성되고 있을까? 미국 시장조사기관 IDC 에 따르면 2020년 기준 <mark>전 세계 디지털 정보량은 60제타바이트(ZB, $10^{21}$ Bytes)</mark> 수준이라고 한다. 지구상의 모든 모래알 수의 약 1,282배에 달하는 양이다. 2025년에는 **175제타바이트**에 이를 것으로 예상된다. 데이터를 여러 도구와 모델로 분석해 새로운 가치를 뽑아내는 능력이 기업과 개인 모두에게 필요해진 이유다.

### 데이터의 형태

데이터는 크게 **정형 데이터**, **반정형 데이터**, **비정형 데이터**로 나뉜다.

#### 1. 정형 데이터 (Structured Data)

<mark>미리 정해진 구조에 따라 저장된 데이터</mark>다. 엑셀 스프레드시트, 관계형 데이터베이스(RDBMS)의 테이블처럼 행(Row)과 열(Column)로 구성된다. 검색, 삽입, 수정, 삭제가 쉬워 정형화된 업무나 서비스에 주로 쓰인다.

### 데이터베이스와 DBMS

데이터베이스(Database)는 <mark>여러 사람이 공유하고 운영할 목적으로 관리되는 통합적인 정보의 집합</mark>이다. 컴퓨터 시스템에 전자적으로 저장되는 구조화된 데이터 모음이며, 데이터베이스 관리 시스템(DataBase Management System, DBMS)에 의해 관리된다.

DBMS 는 <mark>최종 사용자나 응용 프로그램이 데이터베이스에 접근하는 인터페이스 역할</mark>을 하는 소프트웨어다.

---

### 관계형 데이터베이스

관계형 데이터베이스(Relational Database)는 <mark>관계형 데이터 모델</mark>을 기반으로 한 데이터베이스다.

#### 테이블 (Table)
- <mark>릴레이션(Relation)</mark>이라고도 하며, 동일한 주제의 데이터 집합으로 이루어짐.
- 1개 이상의 열과 0개 이상의 행으로 이루어진 데이터 집합.
- 데이터베이스 내에서 유일한 이름을 가져야 함.

#### 열 (Column)
- <mark>속성(Attribute), 필드(Field)</mark>라고도 함.
- 의미가 더 이상 분리되지 않는 최소의 데이터 단위.
- 한 테이블 내에서 유일한 이름을 가져야 하며, 문자·숫자·날짜 등 자신만의 데이터 타입을 가짐.

#### 행 (Row)
- <mark>튜플(Tuple), 레코드(Record)</mark>라고도 함.
- 관련 있는 열의 묶음.
- 한 테이블에 저장된 모든 행은 동일한 수의 열을 가짐.

#### 관계 (Relationship)
- 두 테이블이 서로 연결되는 방식. 데이터의 종속성을 표현함.

#### 기본키 (Primary Key)
- 주된 식별자.
- <mark>한 테이블 내에서 행을 구별할 수 있는 열 또는 열의 묶음.</mark>

## SQL의 개요

### SQL을 배워야 하는 이유

- SQL 은 <mark>데이터에 접근하기 위한 가장 보편적인 수단</mark>이다.
- 아마존 레드시프트 ML, 구글 빅쿼리 ML, 스노플레이크, 오라클 클라우드 인프라 데이터 사이언스, 마이크로소프트 SQL 서버 머신러닝 서비스 같은 클라우드 기반 머신러닝 플랫폼에서도 SQL 을 쓴다.

### SQL의 개념과 역할

SQL(Structured Query Language)은 <mark>IBM 이 1970년대에 개발한 SEQUEL 을 기반으로 만들어진 언어</mark>로, 관계형 데이터베이스 관리 시스템에서 데이터를 다루는 표준 언어다.

데이터베이스와 테이블 생성, 데이터 검색·추가·수정·삭제, 트랜잭션 처리, 보안과 권한 제어까지 데이터베이스의 거의 모든 측면을 SQL 로 관리한다.

### SQL의 특징

- <mark>배우기 쉽고 사용하기 용이</mark>: 영어 문장과 비슷한 구문이라 학습이 빠르다.
- <mark>절차적이지 않음</mark>: 연산을 절차 없이 집합 단위로 처리한다.
- <mark>사용자 편의 중심 언어</mark>: 사용자가 원하는 데이터를 얻는 데 집중한다.
- <mark>미국표준협회(ANSI) 표준</mark>: 표준에 맞춰 작성하면 상용 RDBMS 사이의 호환과 전환이 쉽다.

### SQL문의 종류

#### 1. 데이터 정의어 (DDL, Data Definition Language)

<mark>데이터베이스의 구조를 정의</mark>할 때 쓰는 언어.

| 명령어 | 역할 |
| --- | --- |
| `CREATE` | 데이터베이스 객체(테이블, 뷰, 인덱스 등) 생성 |
| `ALTER` | 기존 객체의 구조 변경 |
| `DROP` | 객체 삭제 |
| `TRUNCATE` | 테이블 내 모든 데이터 삭제 |

#### 2. 데이터 조작어 (DML, Data Manipulation Language)

<mark>데이터를 추가·수정·삭제하고 조회</mark>하는 언어.

| 명령어 | 역할 |
| --- | --- |
| `SELECT` | 조건에 맞는 데이터 검색. DML 에 포함하기도 하고, 데이터 질의어(DQL)로 따로 떼기도 한다 |
| `INSERT` | 새로운 레코드 삽입 |
| `UPDATE` | 데이터 값 수정 |
| `DELETE` | 데이터 삭제 |

#### 3. 데이터 제어어 (DCL, Data Control Language)

<mark>데이터 접근 권한을 제어</mark>하는 언어.

| 명령어 | 역할 |
| --- | --- |
| `GRANT` | 특정 사용자에게 권한 부여 |
| `REVOKE` | 기존 권한 철회 |

#### 4. 트랜잭션 제어어 (TCL, Transaction Control Language)

<mark>데이터 변경 사항을 확정하거나 되돌리는</mark> 언어.

| 명령어 | 역할 |
| --- | --- |
| `COMMIT` | 변경된 내용을 영구 저장 |
| `ROLLBACK` | 변경 사항을 취소 |
